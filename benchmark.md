# ManiSkill — Benchmark Guide

Generated by `benchmark-env-generator` skill. English-only by contract; regenerated on every re-run.

## About

ManiSkill is a large-scale robotic manipulation benchmark built on SAPIEN. It ships GPU-parallel simulation, a gymnasium-compatible API, dense / sparse reward variants, and ~40 registered tasks spanning tabletop (PickCube, PushCube, StackCube), articulated (OpenCabinet, TurnFaucet), dexterous (AllegroHand), and mobile manipulation scenarios. The SAPIEN backend gives it PhysX-5 contact physics, ray-traced rendering, and GPU-side state cloning — the same `env.step(...)` call advances thousands of parallel envs on one GPU.

| Field | Value |
|-------|-------|
| Simulator | SAPIEN + PhysX 5 (GPU) |
| Benchmark category | **IL + RL (dual-track)** (RL native; IL WebSocket eval layer added by skill) |
| Upstream paper / project | <https://maniskill.ai/>, ICLR 2023 (ManiSkill2) and follow-ups |
| License | Apache-2.0 |
| Primary use case | RL / IL for single-arm manipulation; sim2real via GPU domain randomization |

## Tasks

The benchmark exposes **~40+** registered envs. The runnable list (`REGISTERED_ENVS` minus `EVAL_TASK_BLACKLIST` in `mani_skill.utils.run_utils`) is dynamic — print it with:

```bash
docker exec maniskill_container micromamba run -n maniskill python scripts/run_demo.py --list_tasks
```

Representative tasks:

| Identifier | Description | Group |

## Action / Observation spaces

| Field | Value |
|-------|-------|
| Action dim | `8` (default: Panda 7-DoF arm joint delta + 1 gripper with `pd_joint_delta_pos` controller) |
| Action semantics | Joint deltas in roughly `[-1, 1]` (scaled by controller); gripper is `[-1, 1]` → `[open, close]` |
| Observation type | `state` (low-dim vector), `rgbd` (RGB + depth), `rgb`, `pointcloud` — switchable via `--obs_mode` |
| Control frequency | 20 Hz default (decimation=5 at 100 Hz sim) |
| Reward signal | Dense shaped reward (multi-term: distance + grasp + goal) + sparse `success` flag; RL-ready |

Action dim changes with robot and controller. Verify for your config:

```bash
docker exec maniskill_container micromamba run -n maniskill python -c "
import gymnasium as gym, mani_skill.envs
env = gym.make('PickCube-v1')
print('action_dim =', env.action_space.shape[-1])
"
```

## How to use

The skill produced three receipt files at the repo root — `install.md` (how to build), `history.md` (what the skill did), and this file (what the benchmark *is*). The flow below assumes you have already followed `install.md` and have a running `maniskill_container`.

### 1. Enter the container

```bash
docker compose -f docker/docker-compose.headless.yaml up -d
docker exec -it maniskill_container bash
```

### 2. Pick a task

```bash
python scripts/run_demo.py --list_tasks
```

Any identifier from the printed list is a valid value for `--env_id`.

### 3a. IL workflow — stand up a policy server

For a smoke test, use the companion random-policy server (ships with the image):

```bash
python tests/test_random_policy_server.py --port 8000
```

For real evaluation, replace it with any server that speaks the `policy_websocket` protocol and advertises `action_dim=8` in its metadata handshake (`scripts/run_eval.py`'s guard enforces the match).

### 3b. IL workflow — run a single-episode demo

```bash
python scripts/run_demo.py --policy_server_addr localhost:8000 \
    --env_id PickCube-v1 --num_resets 1
```

This is the "show me one rollout" entry point. Writes a per-run dir under `./logs/demo/PickCube-v1--<timestamp>/` containing `demo.log` + `episode=*.mp4`.

### 3c. IL workflow — run multi-episode eval

```bash
python scripts/run_eval.py --policy_server_addr localhost:8000 \
    --env_id PickCube-v1 --num_trials 10
```

Prints rolling + final success rate across `--num_trials` rollouts. Success semantics follow ManiSkill's `info['success']` flag (boolean from the env's reward function).

### 4. RL workflow — train a policy (sb3)

```bash
python scripts/train_rl_policy.py --config-name ppo \
    env_id=PickCube-v1 total_timesteps=1_000_000
```

Supported algorithms: `ppo, sac, td3, ddpg, dqn, a2c` (baselines mode: `sb3`). Configs in `conf/{ppo,sac,td3}.yaml`.

Fast smoke check (≤ 1 minute):

```bash
python scripts/train_rl_policy.py --config-name ppo \
    env_id=PickCube-v1 total_timesteps=5000 n_envs=1 wandb=null
```

Saves a checkpoint under `/workspace/.sb3_checkpoints/ppo/ppo--PickCube-v1--<timestamp>/`.

### 5. RL workflow — evaluate a checkpoint

Currently `run_eval.py` is WebSocket-only (IL path). For RL evaluation, wrap the saved sb3 policy in a `policy_websocket` server (mirrors `tests/test_random_policy_server.py` but calls `model.predict` instead of random) and point `run_eval.py` at it. Alternatively use sb3's native `evaluate_policy` helper directly on the env.

## Troubleshooting

- `ConnectionRefused` on `run_eval.py` / `run_demo.py` → no policy server on the configured port. Start `tests/test_random_policy_server.py` first (IL), or launch your own trained-policy server.
- `ValueError: server action_dim=N != expected 8` → the policy server advertises a different action dim. Fix the server's `ACTION_DIM` constant or change your robot / controller combination to match.
- `RuntimeError: PhysX GPU not initialized` → re-run the Dockerfile's PhysX warmup (`python -c "import sapien.physx as physx; physx.enable_gpu()"`) inside the container.
- Task name not recognized → run `run_demo.py --list_tasks` to see the current dynamic list (a task may have been blacklisted in `EVAL_TASK_BLACKLIST`).
- GUI apps fail with `cannot open display` → you are on the headless compose profile. Switch to `docker-compose.x11.yaml` after `docker compose down`.
- `Vulkan device 0 not available` → host missing `vulkaninfo` or NVIDIA Vulkan ICD. Reinstall NVIDIA Container Toolkit on host.
