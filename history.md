Root cause: `mani_skill/utils/visualization/jupyter_utils.py` unconditionally `from IPython.display import HTML, display`, which pulls in `sqlite3`, which pulls in the bundled libstdc++ that's newer than the one shipped with `nvidia/cudagl:11.3.1-devel-ubuntu20.04`. ### Known limitations

- **`ACTION_DIM=8` was confirmed**, not assumed: L2 capability probe returned `env.action_space.shape[-1] = 8` for `PickCube-v1 + panda + pd_joint_delta_pos`. Still hard-coded in `tests/test_random_policy_server.py`; edit the constant if you switch to a non-Panda robot (e.g., `pd_ee_delta_pose` → 7) before running L3_IL.
- **`import mani_skill` (top-level) throws `CXXABI_1.3.15 not found`** via the `jupyter_utils.py` → IPython → sqlite3 → libstdc++ chain. `import mani_skill.envs` is unaffected — every script in the repo uses the submodule path, so no smoke-test path tripped on this. See capability-probes note above for the 1-line fix (make the IPython import lazy or prepend `LD_LIBRARY_PATH=/opt/conda/envs/maniskill/lib`).
- The sb3 `_ManiSkillCPUAdapter` in `scripts/train_rl_policy.py` assumes single-env (`num_envs=1`) ManiSkill envs and does a cuda-tensor → numpy copy each step. Good enough for the 5k-step L3_RL smoke (achieved ~520 fps on a 570-series driver). For production training, swap in sb3's `VecEnv` wrapper around ManiSkill's native batched env directly so the full GPU parallelism is preserved.
- `docker/entrypoint.sh` does not include a SAPIEN physx shader-cache warmup beyond the build-time `physx.enable_gpu()`. Per the case study this is nominally required; first GPU rollout in a fresh container may pay a one-time shader compile cost (not observed during this run, but future rebuilds might).
- `docker compose down --remove-orphans` during container restart removed the sibling `loco-mujoco_container` and `act_container` on the host (they were cleaned as "orphans" of a shared compose project scope). Users running multiple benchmark containers should bring them back up manually after any maniskill compose cycle, or drop `--remove-orphans` from the standard teardown.
